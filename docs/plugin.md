# 拾念插件：电脑与手机共用

插件源码在 `plugins/shinian/`，公开包不带个人仓库地址、令牌或本机路径。它包含拾念工作流与已注册的官方 GitHub 应用依赖。现有本地 Skill 仍可用于 Codex；不需要同时调用两份。

## 安装到 ChatGPT 账号

1. 从拾念 Web「与 AI 一起创作」下载插件 ZIP，或使用 `web/integrations/shinian-plugin.zip`。
2. 在 ChatGPT 网页「插件 → 添加 → 上传插件压缩包」导入，然后安装。不要仅复制文件到本机技能目录。
3. 按提示连接 GitHub，允许访问自己的资料仓库。安装插件不会授予额外仓库权限。
4. 新聊天选择 `@拾念`。同一 ChatGPT 账号的手机端使用账号内的插件；若移动端没有出现，先检查登录账号、插件安装状态和客户端支持范围，不能把本地安装当作云端已就绪。

## 共用 Web 配置

拾念 Web 的登录和设置保存在浏览器。ChatGPT 无法直接读取它们，因此首次需要一次显式共享：

1. 在 Web「同步设置」保存仓库、分支与令牌。
2. 点「共享 / 更新仓库配置」。它使用**已保存**的设置；刚填但未保存的输入不会被共享。
3. 在插件说“打开我的拾念创意库”。插件通过当前 GitHub 账号读取云端配置；后续新聊天不需再贴仓库地址。

共享只在资料仓库默认分支提交 `.shinian/connections/<GitHub 数字用户 ID>.json`。其中是账号编号、仓库、资料分支、更新时间；没有令牌或游戏内容。Web 与 ChatGPT 必须使用同一个 GitHub 账号且都有权限访问该仓库。共享不会自动上传本机主题。

没有 Web 配置时，直接对插件说“配置并记住我的资料仓库”；选择已有仓库和分支即可。配置写入成功才算记住。没有写权限、分支规则拒绝或 GitHub 授权失效时，保留当前对话草稿并说明原因，不自动创建仓库或改权限。

更换默认库后更新配置；多仓库以当前账号最新有效配置为准。发现过程只读取可访问仓库元数据和自己的连接文件。搜索未索引、分页不完整、超过 200 个候选或限流时，会请用户提供定位提示，不把失败当作“尚未配置”。Web 的本机断开/清除登录不会删除 GitHub 配置。

## 日常流程

“打开创意库” → “继续讨论某主题” → “整理本次讨论” → “保存已确认内容”。插件保存后 Web 点拉取，Web 编辑后点上传。不同平台通过共同资料接续，聊天全文不会自动存入仓库。整理时主动筛选用户上传的有价值参考图，说明用途和正文位置；用户要求保存时默认包含这些图。插件包含图片准备脚本，需要当前环境能读取附件原文件并运行文件处理工具（例如支持该能力的 ChatGPT Work / Codex），不是仅看见图像即可上传。拿不到原文件时明确列出未保存图片，默认不提交缺图文档；用户可选择先存文字。脚本不要求用户电脑常驻，普通聊天的文件处理能力以当前实际工具为准。

图片压缩为静态 WebP（最长边 2560、单张最多 1.5 MiB）；动画只取首帧。图片 blob、正文引用、附件元数据和 v2 标记作为同一次提交保存。图片分析、图片文件访问、GitHub 上传是三个独立能力，插件不伪造缺少的环节。

## 维护与验收

插件0.4.1增加完整决策协议：保存触发条件、结果、例外、理由、来源和未定边界，禁止仅记录“参考某作品”；修正时更新冲突旧文及接续入口。继续讨论时先研究再筛选人工问题。主题特有授权和接续进度保存在资料库，跨设备重新读取，不依赖旧聊天。网页0.4.3同步更新复制上下文的接续提示。

生成新包不代表账号内旧插件已更新；需通过账号插件更新入口上传。离线、未连接GitHub或仍使用旧包的设备不能承诺自动应用新规则。

工作流唯一源是 `.agents/skills/game-idea-vault/`。修改后运行 `python3 scripts/package_plugin.py` 生成插件目录和 Web 下载包，再通过 ChatGPT 的插件编辑/更新入口上传新包。此脚本只打包，不运行测试、不访问 GitHub。上传云端的版本不会随源码提交自动更新。

修改 Web 缓存资源时同时提升 `web/sw.js` 缓存版本。源码推送触发 Pages 发布 Web；云端插件更新与 Pages 发布是独立步骤。

遵照项目要求，功能、手机端及首次读写交由人工验收。安装成功和配置提交成功不代表功能测试通过。
