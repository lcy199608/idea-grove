# 完整决策与跨聊天接续

聊天不是资料库。用户要求保存讨论时，逐项盘点尚未同步的采用、修正、例外、否决和后续安排；不得因“上下文已经说清”而省略。只保存相关决策与必要依据，不保存完整聊天。

## 独立可理解的记录

每项按实际需要写清：对象和适用范围；触发与前置条件；处理步骤或优先级；成功、失败、取消和异常结果；资源、次数、奖励和状态变化；例外与边界；原因和舍弃的关键替代；确认状态及来源；未定参数和下一步。简单决定不必硬凑模板，但影响实施的条件不得省略。

禁止以“参考小XXX”“沿用原版”“按前文”“其他采纳”替代具体规则。引用参考作品时，展开采用的机制，记录本项目修改及不采用部分；附版本、文件和函数/页码等可复核位置。只有来源链接而无规则正文不算完成。不能把推断或玩家描述写成已核实源码事实。

例：不要只写“挑战奖励参考原作”。应写“同次挑战全部必需敌人被有效消灭后一次结算；并行挑战各自判断；取消、超时或清理单位不算成功；部分击杀不发挑战收益”，并按实际已知内容补全次数、消耗、暂停等边界。此例不是所有主题的默认玩法。

## 状态和授权

- 用户明确采用的结论为 confirmed。用户修正优先于此前建议，同步替换冲突表述及旧待讨论入口，保留必要修正理由。
- 用户已授权普通适配与保存时，常规方案直接推进和保存为 exploring，正文标记“授权范围内的AI采用方案，作为当前工作起点，无需逐项询问”。保存不等于实机验证或用户逐条确认。待平衡参数不要伪装成必须人工决定的核心分歧。
- 原图事实、分析推断、手游已确认决定、AI方案和人工观察任务分开表达。人工观察未完成不等于需要现在提问；不把“待研究”变成用户选型问卷。
- 用户要求保存的范围内包含所有相关新决策；范围外保持原状。普通讨论无写入授权仍不保存，不因本协议新增永久权限。

## 提问前过滤

先读取最新主题、相关已决模块和附件明细，检查是否已有答案、是否能进一步研究、是否属于已授权常规适配。按三类分流：AI继续研究/配置；人工实机或样例观察；确需用户取舍。只有最后一类才提问，并给出具体冲突、已有证据、可选方案及影响。不得为维持聊天而制造问题；没有关键分歧可明确说本轮无需提问并继续授权工作。

主题特有的授权范围、讨论偏好和人工参与标准应存为该主题可读取记录；仓库记录不扩大当前系统权限或授权执行无关操作。

## 保存覆盖与接续检查

写入前人工阅读本轮“决策 → 模块 → 摘要/路线图”的对应关系；同时更新失效的待确认、下一问题和旧结论，不能只在末尾追加一段造成前后矛盾。保留无关内容、稳定ID、创建时间和未知字段。按GitHub工作流原子提交，不通过运行游戏或测试来代替内容复核。

接续记录至少包括当前阶段、已完成产物及版本、未完成事项、下一步及负责人/判断类型、资料入口和研究局限。以最新模块为准，历史附件快照不能覆盖新决定。正文承载完整规则，摘要帮助导航，两者不能互相替代。

分支更新成功后才报告同步，并附提交链接。每次新聊天/新设备重新读取远端；不能保证未连接GitHub、未更新插件或离线设备自动得到数据。插件包生成、源码发布、账号插件更新分别报告，不能把本机修改说成所有设备已经升级。
